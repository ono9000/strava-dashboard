# ES/EN i18n (cookie + SSR) Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the entire StravaDashboard UI viewable in Spanish and English with SSR-correct language (no hydration flicker) using a `lang` cookie as source of truth and a simple EN/ES toggle.

**Architecture:** Keep URLs unchanged (no `/en` prefix). Store selected language in a `lang` cookie readable by Server Components. Provide a small i18n layer (`messages` + `t()` helpers) for both server and client usage, and a client toggle that updates cookie/storage and triggers `router.refresh()` so SSR re-renders in the chosen language.

**Tech Stack:** Next.js 14 App Router, TypeScript, React 18.

## Task 1: Add i18n primitives (messages + server helpers)

**Files:**
- Create: `lib/i18n/types.ts`
- Create: `lib/i18n/messages.ts`
- Create: `lib/i18n/server.ts`

- [ ] **Step 1: Create language types**

Create `lib/i18n/types.ts`:

```ts
export const LANG_COOKIE = 'lang' as const
export type Language = 'es' | 'en'
export const DEFAULT_LANG: Language = 'es'

export function isLanguage(v: unknown): v is Language {
  return v === 'es' || v === 'en'
}
```

- [ ] **Step 2: Create messages dictionary**

Create `lib/i18n/messages.ts` with a typed structure (single `Messages` shape shared across languages). Include all strings currently visible in:
- landing page
- dashboard headings/buttons/error states
- all components that render labels/empty states

Expected: `messages.es` and `messages.en` exist and have the same keys.

- [ ] **Step 3: Add server-side language resolution**

Create `lib/i18n/server.ts`:
- Use `cookies()` from `next/headers`
- Read `LANG_COOKIE`
- Fall back to `DEFAULT_LANG`
- Export helpers:
  - `getLangFromCookies(): Language`
  - `getServerMessages(): Messages`

## Task 2: Add client provider + translation hook

**Files:**
- Create: `lib/i18n/client.tsx`

- [ ] **Step 1: Implement `LanguageProvider`**

`LanguageProvider` should:
- initialize from a server-provided `initialLang`
- expose `lang` + `setLang(nextLang)`
- when changing, persist to `localStorage` and call the API route to set the cookie
- then call `router.refresh()` to re-render Server Components in the new language

- [ ] **Step 2: Implement `useT()` helper**

Provide a `useT()` that returns the current `messages` object (or a simple `t(path)` if preferred). Keep it simple and typesafe.

## Task 3: Add API route to set lang cookie

**Files:**
- Create: `app/api/i18n/lang/route.ts`

- [ ] **Step 1: Create POST route**

Implement `POST` that accepts JSON `{ lang: 'es' | 'en' }` and sets `lang` cookie:
- httpOnly: false (so client can also read if needed; server will read via `cookies()`)
- sameSite: 'lax'
- secure in production
- path: '/'
- maxAge: ~1 year

Expected: returns 204 or JSON ok.
